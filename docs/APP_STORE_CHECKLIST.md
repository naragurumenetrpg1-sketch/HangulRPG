# App Store 公開までの手順と確認リスト

> 作成日：2026年11月22日。Apple の規則や画面は変わるので、迷ったら必ず公式の最新情報を確認してください。
> このゲームは「ブラウザ向けのHTMLゲーム」です。iPhone の App Store に出すには、**iOSアプリの“入れ物”に包む作業**（Mac と Xcode が必要）と、**Apple への申請**が要ります。この文書はその全体の流れです。

---

## 1. コード側で、もう済んでいること

| 項目 | 内容 |
|---|---|
| 利用規約・プライバシーポリシー | アプリ内（せってい → アプリの じょうほう）と、公開用ページ（`privacy.html` `terms.html`）の両方 |
| 初回の同意画面 | 初めて起動したときに表示。同意の記録は端末内だけ |
| 問い合わせ・サポート | アプリ内と `support.html` に、連絡先とよくある質問 |
| ライセンス表示 | `licenses.html` とアプリ内（フォントのSIL OFL表示） |
| データ削除 | 「データをすべて消す」（2段階の確認つき） |
| 外部通信ゼロ | Googleフォントをやめて、フォントを同梱。広告・解析・ログインもなし |
| オフライン動作 | `sw.js`（ブラウザ版）。iOSアプリ版では、ファイルをアプリに同梱するので不要 |
| アイコン | `icons/`（**仮のもの**。差し替えてください） |

## 2. 公開前に、あなたが必ずやること

### 2-1. `js/app-info.js` を書きかえる（最重要）
`APP_INFO` の次の4つは、今は仮の文言です。**このまま申請すると、プレースホルダーが残っているとして審査で落ちます。**

- `developer` … 提供者の名前（個人なら本名または屋号、法人なら会社名）
- `email` … お問い合わせ用のメールアドレス（実際に届くもの）
- `effective` … 制定日（公開日）
- `siteUrl` … サポートページのURL（なければ空のままで可）

書きかえたら、`privacy.html` を開いて、名前とメールが入っているか確認します。

### 2-2. 公開用ページをインターネットに載せる
App Store Connect には、**プライバシーポリシーのURL**（必須）と**サポートURL**（必須）を入力します。リンク切れ（404）だけで審査に落ちることがあります。

- GitHub Pages を使う場合：リポジトリの Settings → Pages で公開すると、
  `https://（ユーザー名）.github.io/HangulRPG/privacy.html` のようなURLになります。
- 公開後、**ブラウザでURLを開いて、実際に表示されるか**確認してください。

### 2-3. 素材の権利を確認する
- 画像（ドット絵、タイトル画像など）が、**商用利用・ストア配布できる権利**を持っているか。生成AIで作った画像は、使ったサービスの利用規約（商用利用の可否）を確認してください。
- 韓国語の単語データ（`vocab-data.js`）の出どころ。他の本やサイトからの転載でないか。
- アプリ名「ことだま！ ハングルクエスト」が、他社の商標とぶつからないか（特許庁の J-PlatPat などで検索）。

### 2-4. アイコンを本番用に差し替える
`icons/icon-1024.png` は、タイトル画像から切り出した**仮のもの**で、解像度が低くぼやけています。
1024×1024 の、**角を丸めていない正方形・透明部分なし**の画像を用意して、`icons/` の各ファイルを作りなおしてください。

### 2-5. 利用規約の文面を確認する
`js/app-info.js` の文面は**ひな形**です。法的な助言ではありません。公開前に、内容が実際の運営（提供者の情報、連絡先、準拠する裁判所など）に合っているか確認し、できれば弁護士など専門家に見てもらってください。

## 3. iOSアプリにする（Mac が必要）

### 準備
- Mac、Xcode（App Store から無料）、Node.js
- **Apple Developer Program**（有料の年間会員。公式サイトで最新の料金と登録方法を確認）

### 手順の例（Capacitor を使う方法）
```bash
# 1) 作業フォルダを作る
mkdir kotodama-ios && cd kotodama-ios
npm init -y
npm i @capacitor/core @capacitor/cli @capacitor/ios

# 2) アプリを作る（com.example は自分のIDに変える）
npx cap init "ことだま！ ハングルクエスト" com.example.kotodama --web-dir=www

# 3) ゲームのファイルを www/ にコピー（sw.js と manifest は入れなくてよい）
mkdir www
cp -r ../HangulRPG/{index.html,css,js,fonts,icons,privacy.html,terms.html,support.html,licenses.html} www/

# 4) iOSプロジェクトを作って、Xcodeを開く
npx cap add ios
npx cap sync
npx cap open ios
```

### Xcode での設定
- **Signing & Capabilities**：Team を選ぶ。Bundle Identifier を決める。
- **Display Name** と **Version / Build** を設定する。
- **Info.plist**：`ITSAppUsesNonExemptEncryption` を `NO`（独自の暗号化を使っていないため）。
- **向き**：縦・横の両方に対応している（Deployment Info の Device Orientation で Portrait / Landscape Left / Right にチェック）。
- **アイコン**：1024×1024 を `Assets.xcassets/AppIcon` に設定（`@capacitor/assets` を使うと、1枚から全サイズを作れます）。
- **起動画面（Launch Screen）**：背景色を `#0b1226` などにそろえる。

### 実機でかならず確認すること
- 縦・横どちらでも、ノッチやホームバーに文字やボタンが隠れないか
- 音（BGM・効果音）が出るか。マナーモードのときの動き
- **韓国語の読み上げ**：端末に韓国語の音声が入っているか（入っていなければ、設定の案内をサポートページに書いてあります）
- アプリを終了して開き直しても、セーブデータが残るか
- 「データをすべて消す」→ 再起動で、同意画面が出るか

### TestFlight
Xcode で Archive → App Store Connect にアップロード → TestFlight で、自分や数人の端末にテスト配布して、不具合がないか確認します。

## 4. App Store Connect での登録

### 4-1. アプリの情報
| 項目 | 入れるもの |
|---|---|
| アプリ名 | 30文字まで（他のアプリと重複しない名前） |
| サブタイトル | 30文字まで（例：たたかいながら おぼえる韓国語） |
| カテゴリ | 「教育」または「ゲーム（ロールプレイング）」 |
| 説明文・キーワード | 韓国語、ハングル、学習、RPG など |
| **サポートURL（必須）** | `support.html` のURL |
| **プライバシーポリシーURL（必須）** | `privacy.html` のURL |
| 著作権表示 | 例：2026 （提供者名） |
| 価格 | 無料（アプリ内課金なし） |

> 「キッズ」カテゴリは、外部リンクや情報収集に厳しい追加ルールがあるので、**選ばない**ほうが簡単です。

### 4-2. App のプライバシー（栄養成分表示のような欄）
このアプリは、**データを収集していません**。「データの収集なし（Data Not Collected）」を選びます。
（広告、解析、ログイン、課金、外部サーバーへの送信は、いずれもありません。公開用ページ・アプリ内の説明と、この回答が**一致している**ことが大切です。）

### 4-3. 年齢制限の質問
2025年から質問が新しくなり、**4+、9+、13+、16+、18+** の区分になっています。2026年11月16日からは、新しい項目も追加されています。
質問には、**実際の内容に沿って正直に**答えてください。このゲームは、モンスターと戦う、ファンタジー風の軽い戦闘表現があります。ユーザー投稿、チャット、ウェブの閲覧、課金、ギャンブルは、ありません。最終的な年齢区分は、質問の答えから自動で決まります。

### 4-4. スクリーンショット
- 1〜10枚、PNG または JPEG。
- iPhone は、**6.9インチ（縦 1320×2868）** が基本。6.5インチ（1284×2778 など）でも受け付けられます。iPad にも対応するなら、13インチ（2064×2752）が必要です。
- 最新の大きさは、App Store Connect の「スクリーンショットの仕様」で確認してください。
- 見せたい場面の例：戦闘とクイズ、町（昼・夕方・夜）、ハングル表、がくしゅうの きろく。
- 画面は、**実際のアプリの画面**にしてください（他社の商標やロゴが写り込まないように）。

### 4-5. 審査メモ（App Review Information）の例（英語で書くと確実です）
```
This is a fully offline Japanese-language RPG for learning Korean (Hangul and vocabulary).
No account or login is required. The app collects no personal data and has no ads,
analytics, or in-app purchases. All progress is stored on the device.
Terms of Use and Privacy Policy are available in-app: Settings > "アプリの じょうほう".
Speech uses the device's built-in text-to-speech (ko-KR) for pronunciation.
```

## 5. 審査で引っかかりやすい点と、対策

| 点 | 内容 | このアプリの状況・対策 |
|---|---|---|
| **4.2 最低限の機能** | 「Webサイトを包んだだけ」のアプリは却下されやすい | 完成したゲームで、オフラインで動き、独自のゲーム性があります。審査メモで、ゲームとして完結していること・端末の音声合成を使うことを書いておく。さらに、触覚（振動）や、学習リマインドの通知などの端末機能を足すと有利 |
| **5.1.1 プライバシーポリシー** | アプリ内とメタデータの両方にリンクが必要。リンク切れも不可 | アプリ内は対応済み。URLが開くか、公開後に必ず確認 |
| **2.1 完成度** | プレースホルダー、壊れたリンク、落ちるバグ | `app-info.js` の仮の文言を必ず書きかえる。実機でひと通り遊ぶ |
| **権利（5.2 など）** | 他者の画像・名前・データの無断利用 | 2-3 を確認 |
| **起動時の同意画面** | 同意しないと使えない作りは、内容が適切なら問題になりにくい | 外部リンクはなく、規約はアプリ内で読めます |

アカウントを作る機能がないので、「アカウント削除」の要件（5.1.1(v)）は対象外です。ただし、データ削除の機能は用意してあります。

## 6. 更新するとき

- **ブラウザ版**：ファイルを更新したら、`sw.js` の `CACHE`（`lumina-v1`）の数字を上げます。
- **規約・ポリシーを変えて、もう一度同意してもらう**：`js/app-info.js` の `legalVersion` を変えます。
- **iOSアプリ版**：`www/` にファイルをコピー → `npx cap sync` → Xcode で Version / Build を上げて Archive → App Store Connect にアップロード。
